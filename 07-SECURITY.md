# Security and public examples

This is an educational repository. The local tool is not a production control plane. Use synthetic data and disposable resources. No credentials are required for the core lessons.

For documentation or non-sensitive bugs, open a public issue with a minimal synthetic reproduction. For a vulnerability involving sensitive details, use the repository host’s private vulnerability reporting feature if enabled. If no private reporting channel is configured, use the host’s security/help process; do not post exploit details or secrets in a public issue to ask where to report them.

If you discover an exposed credential, revoke or rotate it through its issuer and use the hosting platform’s removal/reporting process. Deleting a file from the latest revision does not remove earlier copies or invalidate the credential.

The offline audit looks for common accidental private-path and credential patterns. It cannot guarantee the absence of sensitive material. Review every contribution before making it public.
