# Choose a learning route

## Complete beginner

Start at [lesson 00.01](../02-lessons/00-starting-from-zero/01-what-a-platform-engineer-actually-does.md) and follow every Next lesson link. The first 20 lessons teach commands, files, processes, Python, Git, HTTP, SQLite and tests. Do not skip these because a later tool looks more exciting. The [progression gates](13-beginner-to-senior.md) explain what you should be able to demonstrate.

## Practitioner

If you already program, use Git and diagnose HTTP services, demonstrate the foundation checkpoints, then begin phase 06. Complete phases 06–19, the mechanism projects and the integrated API. Use the OpenTofu and Kubernetes projects for actual runtime/tool practice and record which integrations you ran.

## Product and leadership

Do the beginner overview and local quickstart, then phases 07, 09, 13 and 16–19. Read the advanced implementation lessons to understand the limits behind product commitments. Finish capstone C with actual local evidence and a user-centered adoption plan. Leadership study is not a reason to invent execution results.

## Architecture and security

Demonstrate foundation competence, then take phases 08–12, 14–17 and 20–24. Complete tenant authorization, durable operations, revision guards and recovery. Run the integrated API's negative tests and defend a provider failure boundary. Capstone B requires an implemented control, not only a diagram.

## Placement rule

Skip a lesson only when you can demonstrate its completion gate and explain its failure drill without reading the answer. Knowing a tool's name is not sufficient. [Complete lesson map](../01-COURSE-MAP.md) · [Project map](../05-project-labs/00-PROJECT-MAP.md).
